# The x86_64 Backend

x86_64 is the production architecture: the one that boots to a desktop, drives real hardware, and runs
the full capsule fleet. Its `ArchOps` backend is a set of direct instruction sequences, and it owns the
x86-specific platform discovery. This page documents it. The code is under `src/arch/x86_64/`.

## The ArchOps implementation

The `X86_64` backend (`src/arch/x86_64/abi.rs:26`) is a zero-sized type whose methods are single
instructions or short sequences:

```
  halt()                loop { cli; hlt }
  enable_interrupts()   sti
  disable_interrupts()  cli
  interrupts_enabled()  pushfq; pop; test RFLAGS bit 9 (IF)
  current_cpu_id()      CPUID leaf 1, EBX[31:24] -> local APIC id
  read_time_counter()   rdtsc -> EDX:EAX
  flush_tlb_one(addr)   invlpg [addr]
  switch_address_space  mov CR3, root
```

The CPU id is the local APIC id from CPUID, chosen because it is the identifier the platform IRQ
controller uses to route inter-processor interrupts, so the id the kernel sees matches the id the
hardware routes by. The time counter is `rdtsc`, the invariant timestamp counter that the
[clock](../subsystems/time-and-clock/calibration.md) calibrates to wall time elsewhere. Each method is
`#[inline(always)]` with tightly-scoped inline assembly, so the boundary adds no call overhead over
writing the instruction directly.

## The rest of the backend

The `ArchOps` impl is the leaf; the x86_64 tree under `src/arch/x86_64/` is much larger and holds the
arch-specific machinery the rest of the kernel's subsystems build on:

- the [GDT and TSS](../subsystems/interrupts/idt.md) with the IST stacks,
- the [syscall](../subsystems/syscall/boundary.md) `SYSCALL`/LSTAR entry,
- the [time](../subsystems/time-and-clock/README.md) TSC calibration (CPUID, PIT, HPET),
- the [interrupt](../subsystems/interrupts/controllers.md) IO-APIC and LAPIC,
- the FPU and SIMD setup,
- and the boot memory and framebuffer bring-up from the [handoff](../subsystems/boot/handoff.md).

These are documented with their subsystems; this page is the arch backend that sits beneath them.

## ACPI

x86_64 owns platform discovery through ACPI (`src/arch/x86_64/acpi/`). The ACPI module parses the
firmware tables and exposes the MADT, the HPET address, interrupt source overrides, the IO-APIC data,
the LAPIC address, NMI configurations, NUMA regions, PCIe segments, and the processor list. This is how
the kernel learns the machine's interrupt topology and processor inventory: the
[SMP](../subsystems/smp/README.md) bring-up reads the processor list to start the application processors,
and the [interrupt](../subsystems/interrupts/controllers.md) layer reads the IO-APIC and override data
to route device lines. On the other architectures this role is played by the flatspec
[device tree](platform-discovery.md) instead.
